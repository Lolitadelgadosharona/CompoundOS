# Sync contract

IMPLEMENTED: isolated reference atomic snapshot replacement, merged transaction history, stable connection/owner keys, external account IDs, separate holdings/cash IDs, timestamp/provenance checks and sanitized failures. Complete empty holdings may replace prior holdings only when provider explicitly declares complete; transport failure or incomplete batch never does. Duplicate IDs within a batch fail closed. A repeated identical transaction does not duplicate; changed content under the same ID rejects pending explicit correction design. Position quantity is Decimal, finite, nonnegative; cash/flows permit signed amounts. Unsupported short exposure is rejected, not silently clipped.

Runs report provider/start/completion/counts/accepted/rejected/unresolved/error. Unresolved positions count separately from accepted/rejected and are retained for review. Reference runtime is synchronous: start/completion use supplied synthetic instant; future adapter captures actual start/end independently. last_success is separate from latest failed attempt. CURRENT, STALE, SYNC_FAILED, UNRESOLVED and UNKNOWN are distinct. DELAYED quality remains explicit; current broker inventory alone always recommendation_ready=false. Existing market valuation gates remain authoritative.

Future durable tables: owner-scoped connection; external_account(provider,connection,external_id); sync_run append-only; sync_observation immutable keyed(run,external_record_id); current pointers only updated on complete commit. Unique keys scoped owner/connection/account/resource. Per-connection DB lock; sequence/watermark reject older snapshots; pagination completion markers; provider checksums; transaction corrections append-only. Implement retention only after rights review. Do not replace prior values with zero when unavailable. Preserve last data and stale timestamp.

Retry bounded exponential jitter, timeout budget, no raw exception/payload/token logs. Partial snapshot quarantine; never merge partial quantities into current complete balances. Native currency aggregation preserves USD/CNY/EUR; canonical position aggregation preserves account rows and sums quantities only by canonical UUID. It does not calculate net worth, FX conversion or recommendation readiness. Never combine arbitrary overlapping snapshots; durable account ownership/dedup required before portfolio aggregation.
