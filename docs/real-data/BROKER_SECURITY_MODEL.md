# Broker security model

VERIFIED: no network adapter/token route/credential storage added; capability rejection is allowlist based; no execution methods. Existing Preview host/origin/environment/database/external-route boundary retained. No new credential/config/dependency. Security implementation for live connection is NOT VERIFIED.

RECOMMENDATION: Owner signs into official broker UI only. CompoundOS never collects brokerage passwords. TWS credentials remain in official TWS/IB Gateway; local read-only socket bound loopback with broker-side Read Only enforced and verified. OAuth where officially approved: PKCE when supported, state/nonce, exact callback allowlist, least privilege, encrypted access/refresh token store using OS keychain or envelope encryption with external key management. Never persist tokens in account metadata, AuditEvent, browser storage, logs, Git, backups or reports. Tokens isolated owner/provider; refresh serialized, rotation atomic; invalidate old token after successful replacement; revoke on disconnect/security event. Broker application scopes may include trading: CompoundOS method/capability prohibition remains independently necessary, broad scope must be reviewed before authorization.

Future egress allowlist exact official read endpoints; deny order/transfer/withdrawal and HTTP mutations unless required approved authentication endpoint. No arbitrary URL. Rate-limited reads, bounded response size, timeout/retry without duplicated refresh. Audit connection grant/revoke, sync start/result and normalized counts with no account secrets/raw responses. Audit authorization failures. Mask external account identifiers in UI/logs. Local read-only foundation lacks durable tenant enforcement/concurrency/refresh/revocation tests: those are mandatory before any real connection.

Provider outage preserves last known data, labels failure and blocks new trusted advice until fresh complete data. Unknown instrument, cash currency, corporate action, short/margin liability or stale required observation blocks readiness. Restore rehearsal must encrypt backup and test keys/revocation independently. No market-data/financial payload sent to LLM without Owner consent and provider rights evidence.
