# Owner setup — Paper first, no credentials in CompoundOS

This guide is for Owner-executed local setup, NOT actions performed by Codex. No real account or gateway has been connected/installed/logged in during this Sprint. Read adapter operation with a real session is NOT VERIFIED.

1. In official IBKR Client Portal, confirm account eligibility and Paper account. Settings → Account Configuration → Paper Trading Account exposes Paper username/account number; reset Paper password directly there if needed. Do not copy login credentials into Codex/ChatGPT/Git/.env/docs. Do not open/fund/purchase anything without Owner decision.
2. From [official installation instructions](https://www.interactivebrokers.com/docs/web-api/authentication/cpgw/installation-authentication), download/unzip CPGW. Confirm Java via java -version. On Mac from unzipped gateway directory run ./bin/run.sh root/conf.yaml (use official package's platform launcher). Keep gateway access loopback and official approved local rules; if port5000 busy, use official listenPort instructions. No public exposure.
3. Open https://localhost:5000 (or chosen port) directly and authenticate with the PAPER username. Complete IBKR-required 2FA/challenge directly; do not automate it. Confirm returned account is the intended Paper account; no assumed slider. CPGW default TLS is not trusted automatically. Provide a valid localhost SAN certificate in gateway configuration and export its CA/public certificate to a private local path using approved official/local certificate setup. Adapter will refuse untrusted/mismatched TLS rather than disable verification. Exact certificate generation/install varies by gateway package; this part needs Owner review and is NOT VERIFIED.
4. Create a private local JSON file outside Git containing only the confirmed Paper account reference list, e.g. ["DU<actual-paper-number>"] with actual local value; chmod600. This contains account references, NOT username/password/token. The adapter can accept DU+DEMO public-schema marker; otherwise the exact confirmed account file is required. Never infer LIVE/PAPER from the requested UI label alone.
5. Stop original Owner Preview via scripts/stop-owner-preview.sh, preserving its volumes. The native API and gateway must share Mac localhost: a gateway on Mac is not localhost from inside an API container. Do not use host.docker.internal/expose gateway publicly to work around this restriction. A separate Paper-local DB/Redis project will be used; frontend .next is shared, so do not run both UI profiles simultaneously.
6. Use a reviewed local Python virtual environment with requirements.txt installed (no global install) and frontend npm dependencies. From this worktree run:

```sh
.venv/bin/python scripts/run-ibkr-paper-local.py   --ca-file /absolute/local/path/gateway-ca.pem   --paper-account-file /absolute/private/path/paper-accounts.json   --gateway-port 5000
```

Runner creates a separate local database password600 outside Git, starts only its own DB/Redis at55474/55475, applies local schema0037, seeds its own DEMO workspace, builds frontend with native API mapping and serves API127.0.0.1:8182/Web3882. It forces PAPER, disables live auth, environment provider credentials and Yahoo access. No gateway requests on startup. DO NOT point runner to production DB or export its mixed test data into production. Native runner syntax/help/static checks only during Sprint, actual deployment NOT VERIFIED.
7. Open http://localhost:3882/accounts; IBKR initially NOT CONNECTED/READ ONLY. Choose SYNC NOW only after official Paper login/TLS/account confirmation. Config settings are server-side only; no broker credentials accepted by UI. If eligibility/session/TLS/schema fails, inspect only sanitized error and reauthenticate manually. Do not enable brokerage session/permissions to silence errors without separate review.
8. Compare native balances/quantities/average costs/conids to official Paper UI. Confirm PAPER badge, last sync, unresolved count, data quality and zero strategic target/non-target entries. BRK.B must retain class identity. Dashboard mixed valuation is NOT LIVE; no new trusted recommendation. Repeat sync: current counts do not duplicate. No orders/transfers/withdrawals exist.
9. Choose Disconnect local reads; last-known data remains and valuation stays blocked. Log out/stop CPGW directly to terminate authentication (CompoundOS disconnect is not IBKR revocation). Reauthentication is daily; gateway restart/expiry requires manual login, no automatic keepalive/escalation.
10. Ctrl-C native runner stops its API/Web. Stop only its DB/Redis via docker compose --env-file "$HOME/.local/share/compoundos-ibkr-paper-local/database.env" -p compoundos-ibkr-paper-local -f docker-compose.ibkr-paper-local.yml stop. Preserve volumes. Return to original local Preview via scripts/start-owner-preview.sh, which rebuilds proper routing. Neither step is a production deployment.

LIVE read setup not part of this runbook: only a future explicit Owner request may enable separate live-read authorization; no live credentials/session used now. If CPGW offers a genuine read-only account permission for your approved route, prefer it after official confirmation. Do not confuse the TWS Read Only checkbox with CPGW; no such CPGW switch was verified. The app enforces its own closed read allowlist.
