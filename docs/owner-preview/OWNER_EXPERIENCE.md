# Owner Experience — local Preview only

The Owner’s review called for a calm private AI Family Office, rather than an engineering page index. This sprint stays on codex/compoundos-owner-preview; PR121 remains unchanged.

## Navigation and disclosure

- `/` and `/dashboard`: portfolio value, investment holdings, cash, monthly contribution, current safeguards, monthly proposal, accounts, decisions and educational scenarios.
- `/portfolio`: native allocation, target/drift and risk overview.
- `/investment-plan`: actual contribution proposal, reasons, Policy/Guardian, local simulated Committee and explicit Demo approval/rejection.
- `/accounts`: planned read-only brokers and actual local manual-record availability.
- `/decisions`: recorded date/amount/status/governance, then Journal/evidence/audit details.
- `/settings/household`: household preferences; audit activity is collapsed.
- `/governance/journal` and existing `/investment`: retained deeper records and advanced setup. Existing pages were not deleted.

Level1 answers what matters; Level2 explains why; Level3 exposes calculations/evidence/audit. Preview Sprint labels are removed from normal product copy; engineering context stays in code/docs and advanced records. Existing typography/colors/panels are reused, with responsive tables and navigation.

## Data and financial boundaries

Preview-only GET owner-overview composes the existing dashboard/valuation and actual contribution evaluator, with no candidate, ledger or Audit persistence. Investment-holdings value comes from Valuation.total(position), not a duplicate formula. Proposal rows, percentages, drift, funding/FX and governance are generated by the real deterministic services. Dashboard GET does not request Committee or create decisions. Old opinions are shown as current only after the original context/expiry validator accepts them.

Recommendation amounts are never hardcoded. The actual six-target Preview configuration can direct new capital to BRK.B while VTI/QQQ/VXUS/SGOV/AAPL are above target. The original50/30/10/10 example remains correctly blocked by concentration. No target or threshold was changed to improve a screenshot.

Performance TWR/IRR/CAGR/maxdrawdown and equity exposure are Not available because this data path lacks trusted metrics; placeholder services are not used. Wealth scenarios are a separate educational frontend function: current portfolio plus end-of-month contributions, effective annual6/8/10% converted to monthly compounding,10/20/30 years. Current DEMO FX and contributions are held constant; no fees/tax/inflation or future FX forecast. Scenario state never enters plan generation, evidence, Committee, approval or Policy. This is not an optimizer/backtest or return prediction.

The complete actual flow reuses the existing contribution candidate, privacy confirmation, real evidence/schema/numeric checks, simulated provider, Owner lifecycle, Journal and Audit. Approvals remain PREVIEW_ONLY with zero transactions. A Preview namespace defect was fixed: rejection readers now use the same preview.contribution.rejected action as the writer. Rejected proposals cannot request Committee/approval and duplicate rejection fails. With Preview off the action remains contribution.rejected, so LIVE semantics are unchanged. Audit-only rejections are displayed as such without fabricating confirmed Journal snapshots.

## Broker architecture

BrokerConnectionProvider declares ACCOUNT_READ, POSITIONS_READ, CASH_READ, TRANSACTIONS_READ. FutureOrderCapability is a separate enum; V1 ReadOnlyConnection rejects ORDER_PREVIEW and ORDER_EXECUTE capabilities. No vendor connector, credential handler, network client or execution method is implemented. Directory entries for IB/Fidelity/Schwab are NOT_CONNECTED, READ_ONLY, planned/unavailable. Manual Portfolio Connected means local records exist, not a brokerage login. Future manual imports and approved read-only APIs require provider permission; specific broker API availability is not claimed.
