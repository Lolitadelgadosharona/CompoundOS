# Sprint 011 Slice C — Hardening Addendum

## 1. Analysis Lifecycle (Future Roadmap)

Current state: `perspective_analyses` stores completed analyses with
`completed_at` timestamp. The lifecycle below defines the FUTURE workflow
for LLM output validation:

```
Analysis Generated by LLM
        │
        │ status would be set per the design below
        ▼
┌─────────────────────────────────────────┐
│ GENERATED   Raw LLM output received     │
│             Schema validation pending   │
│             Not yet stored as evidence   │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│ VALIDATED   Schema validation passed    │
│             Structured JSON conforms     │
│             Ready for committee use      │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│ ACCEPTED    Owner reviewed + accepted   │
│             Analysis used in memo       │
│             Stored as evidence item      │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│ FAILED      Schema validation failed    │
│             LLM output malformed         │
│             Logged + retry handled       │
└─────────────────────────────────────────┘
```

**Not implemented in Slice C.** The lifecycle status column will be added
in a future migration when LLM output validation is implemented. Current
design uses `completed_at IS NOT NULL` to indicate completion.

## 2. Provenance Completeness Verification

All required provenance fields from the Sprint 011 Technical Design
are present in migration 0029_perspective_analyses:

| Design Field | Column | Present | Notes |
|---|---|---|---|
| perspective | `perspective` TEXT | Yes | CHECK constraint on 6 values |
| research_run_id | `run_id` FK | Yes | RESTRICT on delete |
| model_version | `model` TEXT | Yes | e.g. 'claude-sonnet-4' |
| prompt_version | `prompt_version` INTEGER | Yes | Tracks prompt template version |
| generated_at | `started_at` + `completed_at` | Yes | Two timestamps for duration |
| confidence | `conviction_score` INTEGER | Yes | 1-10 or NULL |
| structured_output | `analysis` JSONB | Yes | Full LLM output |

**No missing fields.**

## 3. Structured Output Evolution

Current: `analysis` column is JSONB (PostgreSQL JSON binary).

This enables structured querying of analysis contents without string
parsing. Examples of future queries that become possible:

```sql
-- Find all analyses where Value perspective scored high conviction
SELECT * FROM perspective_analyses
WHERE perspective = 'value' AND conviction_score >= 8;

-- Find analyses citing a specific metric
SELECT * FROM perspective_analyses
WHERE analysis @> '{"key_metrics": [{"metric": "P/E ratio"}]}';

-- Aggregate conviction by perspective
SELECT perspective, AVG(conviction_score)
FROM perspective_analyses
WHERE completed_at IS NOT NULL
GROUP BY perspective;
```

**No migration required.** JSONB is already the storage type.
